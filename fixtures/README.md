Generated by `cargo xtask import-fixtures` (task M0-3). **Do not edit by hand**: change the staging directory's `provenance.toml` and re-import. ## Provenance

- **Captured:** 2026-09-22
- **Host:** GNOME 50 test host (AnduinOS 2.0.3 / Ubuntu 26.04, GNOME Shell 50.1, gdm3 50.1, gnome-remote-desktop 50.2 with FreeRDP 3, VAAPI radeonsi H.264), reached from the dev Mac through SSH local forwards on 127.0.0.1 with TLS server name 10.1.2.40
- **Tool:** probe2 (the IronRDP b149f50 reference client from ~/code/drift-spikes) copied to a scratch directory and instrumented to dump TLS certificates, Server Redirection frames, RDSTLS PDUs, raw and ZGFX-decompressed GFX DVC payloads, client GFX PDUs, fast-path pointer updates, Annex-B AVC420 and CLIPRDR data

Capture runs (all on 2026-09-22, client desktop 1280x800 unless noted):

1. **Remote Login** (`:3389`, system daemon), caps `[V8_1{AVC420_ENABLED}, V8{}]`: leg 1 NLA with the
   system credentials, Server Redirection after ~2.4 s; leg 2 RDSTLS to the GDM greeter; the probe clicked
   the "Drift e2e test user" tile and typed the password as Unicode key events; second Server Redirection
   (same routing token); leg 3 RDSTLS into the user session, where `anim.py` (full-screen repaint) ran for 7 s.
2. **Remote Login, progressive:** the same flow with caps `[V8_1{}]` (no AVC): g-r-d answers V8.1 and sends
   RFX Progressive (`WireToSurface2`, codec 0x9) for the greeter.
3. **Reused one-time credentials:** while run 1's successor session was live, a new connection replayed the
   one-time credentials of an already-consumed redirection: RDSTLS AuthResponse result `0x52E`
   (LOGON_FAILURE).
4. **Headless** (`:3392`, the second test user's persistent headless session), caps `[V8_1{AVC420_ENABLED}, V8{}]`:
   mouse moves plus `anim.py` for 7 s.
5. **Headless at scale 200:** 2560x1600 with `DesktopScaleFactor=200`; pointer bitmaps are 86x86 (43x43 at 100).
6. **Clipboard** (headless): GNOME Text Editor select-all + Ctrl+C of a UTF-8 file gave `[CF_TEXT, CF_UNICODETEXT]`;
   Print Screen + Enter in the GNOME screenshot UI gave the named format `image/png` (id 0xD011).

Images were decoded from the captured H.264 with ffmpeg 8 using the g-r-d encoder's matrix,
BT.709 full range (plan §1.4): `scale=in_color_matrix=bt709:in_range=full:out_range=full,format=rgb24`.
The TLS certificate DER inside each target-certificate container (type 0x20, DER encoding) is
byte-identical to `tls_cert_leg1/2/3.der` (plan §1.3).

## Sanitization

Every file was sanitized on import: each known secret (every value in the dev machine's secrets directory, plus the one-time user name and password blob found in each Server Redirection PDU and RDSTLS AuthRequest) is replaced, as raw bytes, UTF-8 and UTF-16LE, by a same-length placeholder cycling `REDACTED`, so PDU length fields stay valid. The import fails if any secret survives. The `Replaced` column counts replacements per file.

## Record format (`*.rec`)

A sequence of records, each a little-endian `u32` byte length followed by the bytes: one GFX DVC payload per record (`*.server.raw.rec`: as received, ZGFX `RDP_SEGMENTED_DATA`; `*.server.rec`: the same payload after ZGFX decompression, i.e. concatenated GFX PDUs; `*.client.rec`: GFX PDUs the client sent), or one fast-path output PDU per record.
